# sipflow — SIP Call Flow & RTP Quality Analyzer

![CI](https://github.com/USERNAME/sip-callflow-analyzer/actions/workflows/ci.yml/badge.svg)

`sipflow` reads a packet capture (`.pcap`) of VoIP traffic and rebuilds every SIP call in it:
who called whom, how the call ended, how long setup took, and how good the audio was.

I built it to understand how emergency calls move over IP networks. Next Generation 911 (NG911)
carries calls as SIP and RTP, so a dropped, slow, or choppy call usually shows up in exactly
these packets.

## What it reports

For each call (grouped by SIP `Call-ID`):

| Metric | What it means |
| --- | --- |
| Outcome | `answered`, `failed` (4xx/5xx/6xx), `cancelled` (abandoned while ringing), or `incomplete` |
| Post-dial delay | INVITE → first `180 Ringing` / `183 Session Progress` |
| Setup time | INVITE → `200 OK` |
| Talk time | `200 OK` → `BYE` |
| INVITE retransmissions | Signs of packet loss or an unresponsive server on the signaling path |
| RTP loss | Lost packets per media stream, from RTP sequence numbers (handles 16-bit wraparound) |
| RTP jitter | Interarrival jitter per RFC 3550 §6.4.1, in milliseconds |

RTP streams are tied to their call by matching the audio IP and port announced in each SDP body.

It also flags problems: failed or abandoned calls, setup over 3 s, loss over 1%, jitter over 30 ms,
INVITE retransmissions, and answered calls with no media (no audio in either direction).

## Quick start

```bash
git clone https://github.com/USERNAME/sip-callflow-analyzer.git
cd sip-callflow-analyzer
python -m pip install -e ".[dev]"

sipflow samples/demo_calls.pcap            # summary table + per-call issues
sipflow samples/demo_calls.pcap --ladder   # add the SIP message ladder for each call
sipflow samples/demo_calls.pcap --json     # machine-readable output
sipflow capture.pcap --fail-on-issues      # exit code 2 if any call has a problem
```

## Sample data

`samples/demo_calls.pcap` is **synthetic**: no real call data is used anywhere in this project.
It is generated by `src/sipflow/synth.py` and contains five scenarios: a clean call, a call with
packet loss and jitter, a busy (486) call, an abandoned call, and a slow call with an INVITE
retransmission. Regenerate it with:

```bash
python tools/make_sample_pcap.py
```

## Project layout

```
src/sipflow/
  sip.py        SIP start-line, header (incl. compact forms), and SDP parsing
  rtp.py        RTP header parsing; loss and RFC 3550 jitter per stream
  analyzer.py   Reads the PCAP, builds per-call state, maps RTP to calls via SDP
  report.py     Text/JSON reports and quality checks
  synth.py      Synthetic capture generator used by tests and the demo
  cli.py        `sipflow` command
tests/          pytest suite (parsers, metrics, end-to-end, CLI)
```

## Testing & CI

```bash
pytest -v
ruff check . && ruff format --check .
```

GitHub Actions runs lint, the test suite, and a CLI smoke test on Ubuntu and Windows across
Python 3.10 and 3.12 on every push and pull request.

## Limitations

- UDP signaling only (no SIP over TCP/TLS, no SRTP decryption)
- IPv4 SDP (`c=IN IP4`); IPv6 not yet handled
- Jitter assumes 8 kHz codecs (G.711/G.729), which covers most voice traffic
